# Governance

## Where things actually stand right now

Sky currently has one maintainer. This document describes the real, current decision-making process — not an aspirational structure with roles nobody's filling yet. It's written to expand honestly as people join, not to pretend a committee exists before it does.

## How design decisions get made today

- The locked design specification (`docs/design/`) is the reference point for all glyph work. Decisions already made there include their own reasoning — including alternatives that were considered and rejected — specifically so they can be challenged with reasoning, not just overridden.
- Spec changes go through the **Spec Change Proposal** issue template. The maintainer reviews and decides, publicly, in the issue thread — so the reasoning is recorded, not just the outcome.
- Glyph redraws are reviewed against the spec, not personal taste. A PR that matches the documented spec gets merged; one that doesn't gets specific, spec-referenced feedback.

## How this expands

As contributors take on sustained responsibility (multiple accepted glyph redraws, consistent spec-quality contributions), they may be invited to become maintainers with merge rights. There's no fixed contributor count or tenure requirement for this — it happens when it makes sense, decided by existing maintainers.

Once there are 3+ active maintainers, this document will be updated to describe an actual review/voting process for spec changes, rather than single-maintainer judgment. That update happens when the project actually reaches that point, not before.

## Conduct

All governance and design discussion is subject to the [Code of Conduct](./CODE_OF_CONDUCT.md).
